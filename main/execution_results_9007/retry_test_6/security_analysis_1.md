**Omitted Indicators / Attack Patterns and Rationale**

- **x86_64-unknown-linux-esxi.elf (SHA‑256 6cd349ed…)** – ELF binary is native to Linux/ESXi; Windows Sysmon Event ID 1 only records Windows process creations, so this artifact cannot be observed.  
- **win.bin (SHA‑256 dc9938f5…)** – Generic binary file without a Windows executable image; Sysmon does not emit a process creation event for such files.  

- **CVE‑2023‑3519 (Unauthenticated RCE)** – The exploit is a network‑level vulnerability; successful exploitation may not spawn a distinct new process observable by Sysmon, thus it is outside the scope of Event ID 1.  

- **CVE‑2023‑48788 (SQL injection in FortiClientEMS)** – The attack vector is a crafted HTTP request leading to command execution within the FortiClientEMS service. The resulting activity is internal to the service process and does not generate a separate process creation event that Sysmon can capture.  

- **CVE‑2024‑57727 (SimpleHelp path traversal)** – This vulnerability allows file download via HTTP; it does not inherently cause a new process to be launched, so Sysmon Event ID 1 would not record it.  

- **CVE‑2025‑5777 (NetScaler memory over‑read)** – The issue is a malformed request causing a memory over‑read inside the NetScaler appliance; no new Windows process is created, making it unobservable via this event type.  

- **T1078 (Valid Accounts)** – The technique describes credential use; it does not mandate creation of a new process, and detection relies on authentication logs rather than process‑creation data.  

- **T1566 (Phishing)** – Phishing is an initial social‑engineering vector; the observable component would be the execution of a malicious payload after user interaction, which is already covered by the IOC hash‑based rules. The phishing delivery itself is not a process creation event.  

- **T1219 (Remote Access Tools)** – While specific RAT binaries are covered as IOC hashes, the generic behavioral description (e.g., “install as service”) does not produce a distinct, observable process creation without knowing the exact binary name; therefore only the IOC‑based recommendations are included.  

All remaining attack patterns either have at least one observable behavior that can be captured by Sysmon process‑creation events (as listed above) or are covered via the IOC hash‑based monitoring.
