**Omitted IoCs and rationale**  
- x86_64-unknown-linux-esxi.elf (ELF binary) – not a Windows executable; Sysmon Event ID 1 does not capture non‑Windows processes.  
- win.bin (binary without PE header) – not a Windows executable; cannot be observed by Sysmon process‑creation events.  

**Omitted attack patterns and rationale**  
- T1078 (Valid Accounts): the technique concerns credential use, not the creation of a new process, so it cannot be directly observed with Event ID 1.  
- T1566 (Phishing): primarily an initial‑access delivery mechanism; the malicious attachment execution may be seen, but without concrete filenames or hashes we cannot target a specific process creation.  
- T1027.002 (Software Packing): focuses on binary transformation and in‑memory unpacking, which does not inherently involve a distinct process creation that we can filter on.  
- T1219 (Remote Access Tools): while remote‑access agents eventually run as processes, no specific tool names or hashes were provided; thus we cannot produce a concrete IOC‑based rule.  
- T1486 (Data Encrypted for Impact): ransomware payloads are often custom; without known filenames or hashes we cannot create a deterministic hash‑based monitor, and generic encryption tools are already covered under the “cipher.exe / encrypt” behavior.  
- T1190 (Exploit Public‑Facing Application) – only the secondary process spawn (e.g., w3wp.exe → powershell.exe) is observable; the initial exploit traffic is network‑level and outside the scope of process‑creation logging.  
- T1490 (Inhibit System Recovery) – covered by specific native utility commands; other recovery‑disable techniques not involving these utilities are not observable via process creation.  

All remaining techniques have been addressed either through concrete IOC monitoring or through observable process‑creation behaviors that map to the listed ATT&CK techniques.
